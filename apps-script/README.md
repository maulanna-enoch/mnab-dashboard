# apps-script/

The Apps Script project bound to the MNAB Google Sheet (`Reconcile.gs`, `Templates.gs`, `InstallmentsBills.gs`, `Payments.gs`, `EmailImport.gs`, one shared global namespace, one `onOpen()` menu) has historically lived *outside* this repo — edited directly in the Apps Script editor, with updates delivered to the user as text to paste in by hand. That meant no git history, no PR review, and no diffing for these files.

`EmailImport.gs` is the first of those files brought into this folder for version control (see [#83](https://github.com/maulanna-enoch/mnab-dashboard/issues/83)). It is **not** auto-synced with the live Apps Script project — a change here still has to be pasted into the Apps Script editor by hand after merging. Treat this folder as the versioned source of truth going forward: make changes here first, open a PR, then paste the merged result into the Apps Script editor.

`Reconciliations.gs` (the file elsewhere in this repo's comments — e.g. `api/reconcile.js`, `api/_lib/reconcile.js` — referred to as `Reconcile.gs`; same macro, this is its tracked filename) is the second, current as of v3. Same rules apply: not auto-synced, paste the merged result into the Apps Script editor by hand after merging a change here.

`InstallmentsBills.gs` is the third. Same rules apply: not auto-synced, paste the merged result into the Apps Script editor by hand after merging a change here.

`InboxImport.gs` adds "Import Approved Rows from Inbox…" to the Finances menu. It copies rows you've ticked Approve in the separate **MNAB Import Inbox** spreadsheet into `transactions` and writes each one's destination row back to the inbox, so tools that stage transactions never need access to this spreadsheet. It was written in this repo first. To install it, paste it into the editor as a **new** script file named `InboxImport` (Deployer only replaces files that already exist), then paste the updated `Reconciliations.gs` for the menu item.

The inbox has a **Delete After Import** checkbox per row, ticked by default (a blank cell counts as ticked). After each confirmed run, every ticked row is deleted from the inbox whether or not it was imported, so untick any row you want to keep, including staged rows you haven't reviewed yet. The confirmation says how many rows will be deleted and how many of those weren't imported. If the column is missing, the first run adds it and ticks every existing row. The one row it won't delete is one whose Inbox ID already belongs to a different transaction (for example, an ID reused after the original row was deleted); that row is skipped and kept.

**Automatic import.** Finances > Set Up Inbox Auto-Import… installs a trigger that runs every 10 minutes and does the import only between 12:00 and 20:59 Jakarta time (outside that window each run exits immediately; change `autoStartHour`/`autoEndHour`/`autoEveryMinutes` in `INBOX_CONFIG`). An automatic run skips the confirmation and deletes only rows that were imported and are ticked Delete After Import, so unapproved or skipped rows stay in the inbox for review. Runs that change something, new skip reasons and errors are logged to an `Inbox Import Log` tab. Finances > Remove Inbox Auto-Import… turns it off. After pasting, reload the sheet and run the setup item once; it asks for trigger permission the first time.

`Steals.gs` adds "Set Up Steals from the Future…" to the Finances menu. It tracks money borrowed from your future self (credit card cash advances, mutual fund redemptions, paylater, loans, dipping into savings), with the goal that each month's total is lower than the month before. Running it creates two tabs:

- **`Steals`** is a log you fill in by hand, one row per event: Date, Direction (`Steal`, or `Payback` when you put money back, such as topping up the reksadana again), Type, Source, Amount, Fee, Reason, Notes. Month fills in by itself from Date (calendar month).
- **`Steals Summary`** is formulas only. It shows this month vs last month, a status, a streak of finished months that came in lower, the reserves still owed to the future, and a sparkline. Below that is one row per month (months with nothing logged show 0 and count as wins): Steals, change vs last month, Trend (✓/✗), Paybacks, Net, Owed to Future, Fees, and Steals by Type. Owed to Future counts reserve types only (reksadana, savings, loans; `STEALS_CONFIG.reserveTypes`). Credit card cash advances and paylater are left out: paying that bill next month isn't a payback, since next month's income is what pays it.

Running it again repairs the log's columns and validation and rebuilds the summary, after asking first. It never touches your log rows. The log doesn't read or write `transactions`, so the cash advance or redemption still goes into `transactions` as usual. To install it, paste it into the editor as a **new** script file named `Steals`, then paste the updated `Reconciliations.gs` for the menu item. After that, Deployer can update it. The types list is `STEALS_CONFIG.types` at the top of the file. Edit it there and re-run the menu item, so the log's dropdown and the summary's per-type columns stay in sync.

**Grab receipts** (in `EmailImport.gs`, section "GRAB RECEIPTS"). Receipts from Grab, labeled `mnab/grab` in Gmail, never create rows. Each one is matched to the bank's `Grab* A-…` charge row and fills it in: the Payee becomes the product, restaurant or tip, the route, items and times go into Notes, and the Amount is corrected to the receipt total if the hold was different and the row isn't Cleared or Reconciled yet. The booking ID goes into a self-provisioned `Receipt ID` column. Rides, food and tips match by booking ID. GrabExpress receipts don't show the card ID, so they match by date and a held amount between 100% and 125% of the total, and only when exactly one charge fits. Charges that still have no receipt two days later are renamed `[NO RECEIPT] …`, set back to Pending and marked `NONE` in `Receipt ID`; these are likely cancelled rides. Nothing is ever deleted. Setup: create the label, then add a filter `from:(no-reply@grab.com) subject:(receipt OR struk)` that applies it. For rows already in MNAB, run `previewGrabBackfill` first, then run `runGrabBackfill` until the log says it's done.

**Payee rules** (`PayeeRules.gs`). Rules you keep in a `PayeeRules` tab rename and tidy email-imported rows as they're written, e.g. `DANA QROFF * FamilyM` → `DANA - FamilyMart`. Each rule picks the text to match (payee, notes or either), how to match it (equals, contains, starts with, regex; case and extra spaces ignored), and what to set: Payee, Notes (`-` empties it) and/or Transfer. Rules can be limited to one bank (Source) or one account (SOF). Rules run from the lowest Order up, and the first match wins, so put specific rules above catch-alls. Set Payee / Set Notes accept `{payee}`, `{notes}`, `{sof}`, `{amount}`, and for regex rules `{1}`…`{9}`: the text caught by each `( )` in the pattern, counted from the left, with `(?: )` groups not counted. Rules never touch `[NEEDS REVIEW]` / `[FAILED TRANSFER]` / `[NO RECEIPT]` rows, Grab charges (the receipt matcher needs `Grab* A-…`), card-payment legs, or any amount, date, account or Income/Expense. Every email-imported row now keeps the parser's original text in a `Raw Import` column (source, payee, notes on separate lines) and the rule that fired in `Payee Rule`. Both columns are added automatically. **Finances > Apply Payee Rules to Pending Rows…** re-runs the current rules over rows that are still Pending, not Cleared and not Reconciled, from their Raw Import text. It shows every change and asks first. Pending rows imported before this feature get their current text saved as Raw Import. A broken rule is skipped and reported, never fatal. Install: paste as a **new** script file named `PayeeRules`, paste the updated `EmailImport.gs` and `Reconciliations.gs`, reload, and run **Finances > Set Up Payee Rules…** once. It creates the tab with three starter DANA rules:

| Order | Match Type | Pattern | Set Payee |
|---|---|---|---|
| 40 | regex | `^DANA QR(?:OFF)?\s*\*\s*ESB` | `DANA - ESB Restaurant` |
| 41 | regex | `^DANA QR(?:OFF)?\s*\*\s*FamilyM` | `DANA - FamilyMart` |
| 50 | regex | `^DANA QR(?:OFF)?\s*\*\s*(.+)$` | `DANA - {1}` |

The other bound files (`Templates.gs`, `Payments.gs`) are not yet in this folder. Feel free to add them here the same way when they next need a tracked change.

## Deploying from a phone: `Deployer.gs`

`Deployer.gs` adds a private web page, bound to the same Apps Script project, that does the paste for you. You pick a branch and one tracked file and see a preview. Two taps then write that file into the project. Before writing, it saves a numbered snapshot of the project, and a "Roll back" button restores the file from that snapshot. It only ever replaces one existing file, and leaves everything else (including the untracked `Payments.gs` / `Templates.gs` and the manifest) exactly as it was. It's still a manual deploy and nothing runs on a trigger, in line with the "no automated pushes to the live script" decision.

It needs a one-time setup at a computer: turn on the Apps Script API, paste the file in, add two OAuth scopes to `appsscript.json`, and deploy it as a web app that only you can access. The steps are at the top of the file. `Deployer.gs` itself is not deployable through the page, so update it by hand.
